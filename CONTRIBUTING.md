# Contributing to Onyx

Thanks for wanting to help. Onyx is proprietary (see [LICENSE](LICENSE)), so the ways to contribute are a little different from an open-source project.

## Report a bug

[Open a bug report](../../issues/new?template=bug_report.yml) and include:

- what you did, what you expected, and what happened instead
- your Windows version and the Onyx version (Settings → About)
- a screenshot if something looks wrong

Never paste an API key into an issue. If a bug involves a specific folder, describing its structure (or a screenshot of it) is enough; please don't upload personal files.

## Suggest a feature

[Open a feature request](../../issues/new?template=feature_request.yml). The most useful requests describe the problem you're trying to solve, not just the solution, so it's clear why it matters.

## Write an extension

Onyx can be extended with viewers for new file types without touching its code. [EXTENSIONS.md](EXTENSIONS.md) explains how, and [examples/extensions](examples/extensions) has a working example. Extensions you write are yours.

## Code changes

Pull requests can't be merged without a written agreement first, because the license doesn't allow changes to Onyx without permission. If you'd like to work on something, open an issue describing it and ask; if it's a good fit, we'll sort out the details before you start.

## Security issues

Please don't report security problems in public issues. See [SECURITY.md](SECURITY.md).
